Connect Website opens your website the same way a visitor does, so your AI can learn from it. Some websites have a firewall or a "bot blocker" that stops automatic visitors, including PhiXtra. This guide shows you, or whoever looks after your website, how to let PhiXtra in. It usually takes about 2 minutes.

1Why the connection failed

When you click Connect in Store Information › Connect Website, a red box shows the Reason and a Technical detail. These reasons usually mean a firewall is blocking us:

  • "The website refused our visit (403 Forbidden)"
  • "Cloudflare's bot protection on your website stopped us"
  • "The website's server or firewall cut the connection off"
  • "The website says we've visited too often (429)"

Your website is fine for your customers. It's only automatic visitors that get stopped, and PhiXtra is one of them.

2The two things to allow

Every visit from PhiXtra comes from the same server address and carries the same name. Allow one or both of these in your firewall:

Our server address (IP){{ reader_ip }} Our reader's name (user agent){{ reader_name }}
Tip: the server address is the safer choice. Only PhiXtra can visit from it, while anyone could copy a name.

PhiXtra only reads public pages: up to 100 pages each time you sync, slowly, one page at a time. It never fills in forms, logs in or buys anything.

3Cloudflare

If the reason mentions Cloudflare, or the technical detail says server: cloudflare, your website uses Cloudflare. Log in at dash.cloudflare.com and choose your website. Cloudflare sometimes renames its menus, so the names below may be slightly different.

Option A: IP Access Rule (simplest)

  1. Go to Security › WAF › Tools.
  2. Under IP Access Rules, type {{ reader_ip }}.
  3. Set the action to Allow, choose This website, and add a note: "PhiXtra website reader".
  4. Click Add.

Option B: Custom rule

  1. Go to Security › WAF › Custom rules › Create rule.
  2. Name it "Allow PhiXtra". Set the field to IP Source Address, the operator to equals and the value to {{ reader_ip }}.
  3. Choose the action Skip and tick every protection it lists (all remaining custom rules, rate limiting, managed rules, Super Bot Fight Mode where shown).
  4. Click Deploy.
"Bot Fight Mode" (free Cloudflare plans): this setting can't be skipped by a rule. If it's switched on and PhiXtra is still blocked after Option A or B, go to Security › Bots and switch Bot Fight Mode off. On paid Cloudflare plans, "Super Bot Fight Mode" can be skipped with the rule in Option B.

Also check Security › Settings. If "I'm Under Attack" mode is on, every visitor has to pass a check first. Switch it off when you no longer need it.

4WordPress security plugins

Log in to your WordPress dashboard and find your security plugin in the left-hand menu.

Wordfence

  1. Go to Wordfence › Firewall › All Firewall Options.
  2. Find Allowlisted IP addresses that bypass all rules and add {{ reader_ip }} on its own line.
  3. Click Save Changes.

Sucuri

In your Sucuri Firewall dashboard, go to Access Control › Allowlist IP (some accounts say "Whitelist IP"), add {{ reader_ip }} and save.

Other plugins (Solid Security, All-In-One Security, Shield and others)

Look in the plugin's settings for a list called Allowlist, Whitelist, Authorized IPs or Trusted IPs, then add {{ reader_ip }}.

Tip: if your website also uses Cloudflare, do the Cloudflare step as well. Both can block us.

5Your hosting company's firewall

Some hosting companies run their own firewall (for example Imunify360, ModSecurity or cPHulk). You can't usually change it yourself, so send them this message:

Hello, please allowlist the IP address {{ reader_ip }} (user agent "{{ reader_name }}") for my website in your firewall / bot protection. It is PhiXtra, the AI assistant service my business uses, and it needs to read my public pages. Thank you.

6Wix, Shopify, Squarespace

These website builders don't give you a firewall to change, and they usually let PhiXtra in without any setup. If the connection still fails:

  • Check your website is published and not password-protected or in "coming soon" mode.
  • If you've connected your own domain through Cloudflare, follow the Cloudflare steps.
  • Otherwise, send the builder's support team the message in part 5.

7robots.txt

If the reason says your website's robots.txt file asks readers not to read it, your website is telling every automatic reader to stay away. You can let PhiXtra in and still keep the others out. Add these lines at the top of the file:

User-agent: {{ reader_name }}
Allow: /

Where to change it: on WordPress, use your SEO plugin (Yoast: Yoast SEO › Tools › File editor; Rank Math: Rank Math › General Settings › Edit robots.txt). On other websites, ask whoever looks after your website. You can see the file at yourwebsite.com/robots.txt.

8Try again

  1. Go back to Store Information › Connect Website.
  2. Type your website address and click Connect.
  3. A green box saying "Connection successful" means you're done. Go to Sync Website and click Sync now to let your AI read your pages.

If it still fails, look at the new reason. It may be a different problem. Every attempt is listed under Recent connection attempts, so you can send that list to whoever looks after your website.

After you've connected: keep the rule in place. PhiXtra visits again each time you click Sync now, and on paid plans also on your daily, weekly or monthly schedule.

9If you can't change the firewall

Your AI can still learn about your business without Connect Website:

  • Store Information: add your key information (opening hours, delivery, prices, policies, contact details) as entries.
  • AI knowledge documents: upload documents such as a price list, brochure or FAQ.
  • WordPress / WooCommerce shops: use the PhiXtra plugin, which sends your pages from inside your website.
